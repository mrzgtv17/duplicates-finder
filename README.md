# Поиск дубликатов

Программа для macOS и Windows, которая находит одинаковые файлы:

- **в папке или на диске** — сравнивает содержимое файлов (а не имена), поэтому находит копии
  даже с разными названиями;
- **на Яндекс Диске** — через API, без скачивания файлов (по контрольным суммам).

Что умеет: фильтр по расширениям и размеру, таблица с группами копий, удаление лишних копий
в Корзину (с подтверждением; удалить все копии одного файла нельзя), отчёт для Excel
с полными адресами файлов, обновление из самой программы.

## Скачать

Последняя версия: **[Releases](https://github.com/mrzgtv17/duplicates-finder/releases/latest)**

| Система | Файл |
|---|---|
| macOS (Apple Silicon, M1 и новее) | `DuplicatesFinder-macOS.zip` |
| Windows 10/11 | `DuplicatesFinder-Windows.exe` |

**Mac:** распакуйте архив и перетащите «Поиск дубликатов» в «Программы». При первом запуске
macOS предупредит, что разработчик не проверен: откройте *Системные настройки →
Конфиденциальность и безопасность* и нажмите «Всё равно открыть» (один раз).

**Windows:** положите `DuplicatesFinder-Windows.exe` в любую папку (например, «Документы\Программы»)
и запустите. Если появится окно SmartScreen — «Подробнее» → «Выполнить в любом случае» (один раз).
Не кладите программу в `Program Files` — туда ей нельзя записать обновление.

Дальше программа обновляется сама: при запуске она проверяет новые версии, а вручную —
меню **«Обновления → Проверить обновления…»**.

## Разработка: всё через Pull Request

```
ветка с изменением  →  Pull Request  →  проверки и сборка  →  слияние в main  →  релиз  →  обновление у пользователей
```

1. Создайте ветку и внесите изменения.
2. Увеличьте `APP_VERSION` в `app/__init__.py` (1.3.0 → 1.3.1 для исправления, → 1.4.0 для новой функции).
3. Добавьте раздел `## <версия>` в `CHANGELOG.md` — это описание обновления для пользователей.
4. Откройте Pull Request. GitHub Actions автоматически:
   - запустит тесты и проверит, что версия и CHANGELOG в порядке;
   - соберёт `.app` и `.exe` — их можно скачать на странице проверки (раздел **Artifacts**) и
     попробовать до слияния.
5. После слияния в `main` GitHub соберёт программы ещё раз и опубликует релиз `v<версия>`.
   Установленные программы увидят его и предложат обновиться.

PR без изменения версии (например, только README) тоже можно сливать — релиз просто не создаётся.

### Структура

| Путь | Что там |
|---|---|
| `app/__init__.py` | версия программы и адрес репозитория |
| `app/core.py` | поиск дубликатов, Яндекс Диск, Корзина, отчёт CSV |
| `app/gui.py` | окно программы (tkinter) |
| `app/updater.py` | обновление через GitHub Releases |
| `main.py` | точка входа |
| `tests/` | тесты (`pytest`) |
| `scripts/` | сборка (`build_macos.sh`, `build_windows.sh`), проверки версии, иконки |
| `tools/` | версии для командной строки (`find_duplicates.py`, `yandex_duplicates.py`) |
| `.github/workflows/build.yml` | тесты, сборка и публикация релизов |

### Запуск из исходников

```bash
python3 main.py                 # нужен Python 3.10+ с tkinter (python.org)
pip install -r requirements-dev.txt
pytest -q && ruff check .       # тесты и проверка кода
bash scripts/build_macos.sh     # собрать .app локально (на Mac, нужен pip install pyinstaller)
```

### Как устроено обновление

Каждый релиз содержит `DuplicatesFinder-macOS.zip`, `DuplicatesFinder-Windows.exe` и
`SHA256SUMS.txt`. Программа запрашивает последний релиз через API GitHub, скачивает файл для
своей системы, сверяет контрольную сумму, заменяет себя и перезапускается. Файл с неверной
суммой не устанавливается.
